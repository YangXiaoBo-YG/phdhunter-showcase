# Agent 协作与招聘来源治理

记录项目负责人的 AI 辅助产品工作方式，并提供可重复的任务分工。采集脚本、Embedding 与 LLM 精排是已有软件链路；来源调查、独立核验和产品验收是负责人可调用 Agent 完成的工作，不宣称后台已运行完整自主多 Agent 平台。

## 分工

| 角色 | 输入与职责 | 交付 | 不可越过的边界 |
|---|---|---|---|
| 负责人 / 主 Agent | 用户问题、地域和岗位范围，拆解任务并验收 | PRD、字段定义、来源准入、发布判断 | 对产品取舍负责 |
| 来源调查 Agent | 搜索政府、高校、研究院及聚合来源 | 发布主体、原公告、频率、字段与获取方式 | 搜索摘要不替代原文 |
| 公告核验 Agent | 独立回查抽取字段与原公告 | 编制、学历、专业、薪酬、日期与申请链接的证据 | 不凭学校层次推断编制，不补造薪资 |
| 推荐方法 Agent | 研究画像、硬约束、职业偏好 | 召回 / 精排设计、案例和评测方案 | 理由只能依据岗位与用户已给信息 |
| 实现 Agent | 已核定的数据和产品需求 | 采集适配、数据表、接口与页面改动 | 不修改生产密钥或擅自写库 |
| UI / QA Agent | 正常、空值、超时、过期和降级场景 | 截图、复现、测试结果 | lint / build 成功不等于真实业务成功 |

角色按任务规模组合；具体谁执行、是否真正调用独立子 Agent，应写入任务记录，不将职责表当作历史运行证据。

## 来源准入到岗位入库

发现招聘线索 → 确认发布主体和原始公告 → 提取岗位级字段与证据 → 独立复核易错项 → 主负责人确认规则 → 实现适配 → 抽样比较 → 进入数据库和推荐链路。

高风险字段包括：否定编制表述、同一公告不同岗位待遇、截止日期、应届条件、专业目录与学历要求。对于来源冲突，原招聘主体最新明确更正优先；日期和适用岗位必须同时核对，不能自动用“更新页面”覆盖所有历史。

## 避免错误的具体要求

- 保留原公告链接；来源打不开时记录未核验，不让模型续写缺失事实。
- 已知截止日期用于过期判断；日期缺失、解析失败与仍有效分开处理，这是需继续完善的数据治理。
- 当前编制识别为规则和线索推断，输出需要核验；否定句和跨岗位误归类列入回归样本。
- 模型精排应仅引用候选岗位、遵守硬性条件，并标识降级；候选 ID 与响应结构的严格验证属于当前待补项。
- upsert 的处理数量、实际新增、更新、重复与失败分别统计；现有报告尚不能完整区分。
- 用户画像和模型请求只在授权范围内使用，不能复制进公开展示或日志。

|---|---|---|---|---|---|---|

## 更新与异常处理

当前公开工作流只支持主动确认的手动采集；默认检查不调用模型、不写数据库。若恢复定时采集，应先完成来源联调、额度管理及错误告警设计。页面故障、数据过期、抓取失败和模型降级分开跟踪，不用“任务执行成功”掩盖内容错误。
