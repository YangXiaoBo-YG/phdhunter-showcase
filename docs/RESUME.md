# 简历与面试：PhDHunter

## 项目定位

博士个性化求职平台 MVP｜产品负责人、Agent 协作与 AI 推荐流程设计｜Next.js / TypeScript / Supabase / pgvector / 通义千问。

## 可用于简历的表述

- 从博士求职场景出发，主导研究画像、职业偏好、编制标签、筛选 / 推荐 / 收藏等产品路径，组织 AI 辅助实现可运行的 Web MVP。
- 设计来源调查、公告核验、推荐方法、工程实现与 UI 验收的 Agent 分工，用原始招聘公告和岗位级字段核实约束模型输出，保留原文回查入口。
- 组织六类招聘来源适配与清洗 / 标准化 / 复合键去重链路，结合 Supabase pgvector 的 1024 维向量召回与千问精排生成候选建议和推荐理由。
- 明确处理推荐降级、服务端密钥、RLS 与脱敏展示边界；以离线检查和真实联调分层验收，区分代码完成与生产可用。

## 突出的是哪些个人能力

产品研究：将真实求职需求变成字段、约束和用户路径。

AI 应用：选择召回与精排各自解决的问题，处理读写权限、模型异常和成本边界。

Agent 编排：拆分任务、约定交付、引入独立核验与负责人裁决，而非只向一个模型索要整站代码。

验收迭代：用否定编制、混合岗位、过期公告和异常推荐等案例持续校验。

以上职责来自负责人陈述与项目设计；具体执行记录、实现和验证范围分别保留。代码由人机协作完成，不声称全部独立手写。不写未经评测的匹配准确率、实际录用率、用户规模或自动化运营成效。
