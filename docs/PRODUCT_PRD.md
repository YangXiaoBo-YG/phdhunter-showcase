## 核心用户与任务

用户是希望在浙江就业的博士、博士后及相关研究人员。主要问题是招聘来源分散、研究方向与岗位语言不一致、编制与聘用方式难判断，以及薪资、城市、机构和职业路径需同时权衡。

两条路径：直接浏览 / 筛选岗位；或填写研究画像与偏好后查看推荐。两者都应能进入详情、收藏，再回到原始招聘公告。

## 需求与验收矩阵

| 需求 | 已有实现 | 验收重点 / 未完成项 |
|---|---|---|
| 招聘聚合 | 六类来源适配器、HTTP 重试与采集入口 | 每个来源实际可用性需联调，不能按文件数量认定覆盖率 |
| 岗位标准化 | 文本、日期、机构与岗位类型处理 | 原始公告与抽取字段一致，缺失不臆测 |
| 编制标签 | 关键词规则及辅助线索 | 否定句、混合岗位、岗位级适用范围尚需样本验证 |
| 去重与时效 | 复合键 upsert、按已知截止日标状态 | upsert 返回数量不是新增数量；缺失截止日不表示长期有效 |
| 个性化推荐 | 1024 维向量召回、候选排序与理由 | 结构化输出校验、候选 ID 限定和推荐相关性评测需加强 |
| 收藏与交互 | 列表、详情、偏好、收藏与通知 | 完整浏览器路径、移动端和异常状态需持续验收 |

## 来源选择与核实

优先原招聘机构人事部门、政府人社与官方研究院公告；聚合平台用于发现线索，再回查原始公告。新增来源核实发布主体、原文链接、日期、岗位附件和申请入口，不能只按机构知名度或搜索排名判断。

编制以岗位对应原文为准：“未标注”可以接受，无法确认时不补成事业编；含否定、不同岗位聘用方式或辅助线索时交给核验任务。现有规则可能误判，这是待改进项，不宣称已经实现语义级核验。

## 推荐系统与 UI 设计

研究方向、关键词和技能用于向量召回；职业偏好与候选岗位摘要进入精排提示。当前 `matcher.ts` 粗筛 Top 100、模型精排 Top 20，精排失败返回粗筛 Top 50 并标记降级。提示中的权重是设计取舍，不是经过标注数据训练得出的效果结论。

UI 目标是帮助用户核查和行动：列表支持快速筛选，详情保留原始公告，推荐理由说明匹配依据，收藏支持后续比较。推荐分数不能显示或解释为录用概率；错误、空结果和降级状态需要可辨认。

## 自动化与运营

私有开发流程有每周采集设计及历史任务记录；当前公开副本仅手动触发，并要求确认真实采集。不要写成每日持续自动抓取已上线。新增定时任务或调整频率属于后续运营决策，需结合来源更新节奏和服务成本。

每日运营检查可由负责人使用 Agent 辅助完成：公告是否过期、来源解析是否变化、采集是否误报为零、模型异常和额度、推荐是否引用原文没有的条件。该流程是职责设计，不代表公开代码已有常驻自动巡检服务。

## 质量与发布责任

负责人决定来源准入和产品发布；调查 / 核验 Agent 提供证据与异议；实现 Agent 按需求改代码；QA 交付复现和检查记录。Agent 的结论须可回查，不让模型自行授予数据“可信”标签。

发布前分开检查：源码静态检查与离线测试、真实来源和数据库联调、模型结果质量、用户完整操作路径。公开 CI 只覆盖其中一部分，不能等同全部验收。
